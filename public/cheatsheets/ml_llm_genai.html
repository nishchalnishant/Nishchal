    Common evaluation traps

    • Near-duplicate examples across train and test inflate scores; deduplicate before splitting.
    • Tuning on the test set: use a validation set and touch the test set once.
    • Averages hide failing slices; report metrics per segment.
    • An offline gain is not a business gain until an online test confirms it.
    • LLM judges drift: pin the judge model and prompt, and spot-check with humans.
    • Pick the metric for the decision it drives: precision@k for a feed, calibration for a threshold, recall for safety filters.

    02Math and statistics foundations

    The math that interviewers ask you to derive or explain on the spot.

    Linear algebra#

    • Dot product a·b = |a||b|cosθ: similarity, projections, attention scores.
    • Matrix multiply (m×n)(n×p): cost m·n·p; a linear layer is y = Wx + b.
    • Eigen Av = λv; covariance eigenvectors = principal components.
    • SVD A = UΣVᵀ: PCA, low-rank approximation (LoRA intuition), recommender MF.
    • Rank: number of independent directions; low rank → compressible.
    • Norms: L1 (sparsity), L2 (energy), Frobenius, spectral.
    • Positive semi-definite: covariance and kernel matrices; convex quadratic forms.

    Calculus and optimisation#

    • Chain rule is backprop: ∂L/∂x = ∂L/∂y · ∂y/∂x.
    • Gradient points uphill; step against it. Jacobian for vector outputs; Hessian for curvature.
    • Convex → any local minimum is global (linear/logistic regression, SVM).
    • Neural nets are non-convex; saddle points matter more than bad local minima.
    • Lagrange multipliers: constrained optimisation (SVM dual).
    • Learning rate too high → divergence; too low → slow; use warmup + decay.

    Probability essentials#

    Bayes: P(A|B) = P(B|A)·P(A) / P(B) E[X+Y] = E[X]+E[Y]; Var(aX) = a²Var(X) Var(X) = E[X²] − E[X]²
    • Independence: P(A∩B)=P(A)P(B). Conditional independence underlies Naive Bayes.
    • CLT: sample means → normal, std error σ/√n.
    • LLN: averages converge to the expectation.
    • Base-rate fallacy: 99% accurate test on a 1% disease → ~50% precision.

    Distributions to know#

    DistributionModelsMean / var

    Binomial(n,p)Successes in n trialsnp / np(1−p)
    Poisson(λ)Event counts per intervalλ / λ

    Estimation and information theory#

    • MLE: maximise likelihood. Gaussian noise → MSE; Bernoulli → cross-entropy.
    • MAP: MLE + prior. Gaussian prior = L2; Laplace prior = L1.
    • Entropy H(p) = −Σ p log p; cross-entropy H(p,q) = −Σ p log q.
    • KL divergence = H(p,q) − H(p); asymmetric; used in VAEs, RLHF penalty, distillation.
    • Bias–variance: error = bias² + variance + noise. More capacity ↓bias ↑variance.
    • Mutual information: shared information; feature selection.

    Hypothesis tests and A/B testing#

    • p-value: P(data this extreme | H₀). Not P(H₀ true).
    • Type I (α, false positive) vs type II (β, missed effect); power = 1−β, aim 0.8.
    • Sample size per arm ≈ 16σ²/δ² for α=0.05, power 0.8.
    • Tests: t-test (means), z/χ² (proportions), Mann-Whitney (non-normal), bootstrap CIs.
    • Pitfalls: peeking (use sequential tests), multiple comparisons (Bonferroni/BH), novelty effects, sample ratio mismatch, network interference.
    • CUPED: subtract pre-period covariate to cut variance.
    • Guardrail metrics (latency, revenue, complaints) alongside the primary metric.

    03Formulas: metrics, losses, optimisers, model maths

    Write these from memory. Most interview derivations start from one of them.

    Classification metrics#

    Precision = TP / (TP + FP) Recall (TPR) = TP / (TP + FN) F1 = 2PR / (P + R) (Fβ weights recall β times more) Specificity = TN / (TN + FP) FPR = FP / (FP + TN) = 1 − specificity Accuracy = (TP + TN) / total Log loss = −(1/N) Σ [y log p + (1−y) log(1−p)]
    • ROC-AUC = P(random positive scores above random negative); threshold-free.
    • PR-AUC baseline = positive rate; use it when positives are rare.
    • Pick the threshold from business costs, not 0.5.
    • Macro (average per class) vs micro (pool counts) vs weighted averaging.

    Regression, ranking and generation metrics#

    MAE = mean|y − ŷ| RMSE = √mean(y − ŷ)² R² = 1 − SS_res / SS_tot DCG@k = Σ (2^rel_i − 1) / log₂(i + 1) NDCG = DCG / IDCG MRR = mean(1 / rank of first relevant) Recall@k = relevant in top k / all relevant Perplexity = exp(cross-entropy per token)
    • MAPE explodes near zero; use sMAPE or MAE for such targets.
    • BLEU (n-gram precision), ROUGE (recall, summaries), BERTScore (embedding match).

    Loss functions#

    LossFormula / ideaUse
    MSE / MAE / Huber(y−ŷ)², |y−ŷ|, quadratic near 0 then linearRegression; Huber resists outliers
    Cross-entropy−Σ y log softmax(z)Classification, language modelling
    Focal−(1−p)^γ log pHeavy class imbalance, detection
    Hingemax(0, 1 − y·f(x))SVM
    Contrastive / InfoNCE−log e^{s⁺/τ} / Σ e^{s/τ}Embeddings, CLIP, retrieval
    Tripletmax(0, d(a,p) − d(a,n) + m)Metric learning, face ID
    KL divergenceΣ p log(p/q)VAE, distillation, RLHF penalty
    Pairwise rankinglog(1 + e^{−(s_i − s_j)})Learning to rank, reward models

    Optimiser updates#

    SGD: θ ← θ − η g Momentum: v ← βv + g θ ← θ − η v Adam: m ← β₁m + (1−β₁)g; v ← β₂v + (1−β₂)g² m̂ = m/(1−β₁ᵗ); v̂ = v/(1−β₂ᵗ) θ ← θ − η m̂ / (√v̂ + ε) AdamW: same + θ ← θ − ηλθ (decoupled weight decay)
    • Adam memory: 2 extra states per parameter → ~16 bytes/param with fp32 master weights in mixed precision.

    Neural-net building blocks#

    sigmoid(x) = 1/(1+e^−x) softmax(z)_i = e^{z_i}/Σ e^{z_j} Attention(Q,K,V) = softmax(QKᵀ/√d_k) V LayerNorm(x) = γ (x − μ)/√(σ² + ε) + β RMSNorm(x) = γ x / √(mean(x²) + ε) SwiGLU(x) = (Swish(xW₁) ⊙ xW₃) W₂ Dropout: zero with prob p, scale kept units by 1/(1−p)

    LLM sizing maths#

    Params (dense decoder) ≈ 12 · L · d² (+ vocab · d embeddings) Training FLOPs ≈ 6 · N · D (N params, D tokens) Inference FLOPs ≈ 2 · N per token Weights memory = N × bytes/param (bf16 = 2, int8 = 1, int4 = 0.5) Full fine-tune with Adam ≈ 16–20 bytes/param (+ activations) KV cache/token = 2 · L · n_kv_heads · d_head · bytes Attention cost ∝ n² · d per layer
    • 7B in bf16 ≈ 14 GB weights; Llama-style 70B with GQA ≈ 0.3 MB KV per token in bf16.

    • fit/fit_transform on full data before split → leakage
    • fit_transform on test re-learns stats — only .transform()
    • OneHotEncoder needs handle_unknown="ignore"
    • SMOTE only inside CV folds (imblearn Pipeline)
    • Accuracy misleads on imbalance → F1 / PR-AUC / class_weight
    • Set random_state; same CV splitter across models
    • Grid too slow → RandomizedSearchCV

    Boosting libraries compared#

    LibraryDistinctive ideaUse when
    XGBoostSecond-order (gradient + Hessian) objective with explicit regularisation; sparsity-aware splits; histogram modeGeneral default, mature tooling

    Tree split maths#

    Gini(S) = 1 − Σ pₖ² Entropy(S) = − Σ pₖ log₂ pₖ Gain = Impurity(parent) − Σ (|child| / |parent|) · Impurity(child) Regression: choose the split that most reduces variance (MSE)
    • Gini and entropy usually pick similar splits; Gini is cheaper (no logarithm).
    • Information gain favours many-valued features; gain ratio corrects for it.
    • Feature importance from impurity is biased toward high-cardinality features; prefer permutation importance or SHAP.

    Fairness#

    • Demographic parity: equal positive rates across groups.
    • Equal opportunity: equal true-positive rates. Equalised odds: equal TPR and FPR.
    • Predictive parity / calibration within groups: a score means the same probability for every group.
    • Impossibility: when base rates differ, calibration and equalised odds can't both hold; choose with stakeholders.
    • Bias sources: sampling, historical labels, measurement, proxies for protected attributes.
    • Mitigation: pre-processing (reweighing, resampling), in-processing (fairness constraints, adversarial debiasing), post-processing (group-specific thresholds).
    • Process: slice metrics by group, model cards, human review of high-impact decisions.

    10Transformer and LLM internals

    Architecture choices inside modern LLMs, decoding, long context and reasoning models.

    Decoder block, end to end#

    1. Tokenise (BPE) → token IDs → embedding lookup (d_model).
    2. Pre-norm (RMSNorm) → masked self-attention with RoPE on Q and K.
    3. Residual add → pre-norm → FFN (SwiGLU, ~2.7–4× d_model hidden) or MoE layer.
    4. Residual add; repeat L layers.
    5. Final norm → LM head (often tied to embeddings) → logits → softmax → sample.
    Causal mask lets token i attend only to ≤ i. Training is parallel over positions (teacher forcing); generation is sequential.

    Architecture choices#

    ChoiceOptions and why
    Attention headsMHA → GQA (shared K/V per group) → MQA (one K/V); MLA compresses KV into a latent (DeepSeek)
    PositionsAbsolute learned/sinusoidal → RoPE (relative, rotates Q/K) → ALiBi (linear bias)
    Long contextRoPE scaling (position interpolation, NTK, YaRN), sliding-window attention, ring/sequence parallel attention
    NormPost-LN (original) → pre-LN (stable deep training) → RMSNorm (cheaper)
    FFNReLU/GELU → SwiGLU (better quality per FLOP)
    MoERouter picks top-k experts per token; more parameters at same compute; load-balancing loss, expert parallelism
    Efficient attentionFlashAttention (exact, IO-aware), linear attention, state-space hybrids (Mamba, Jamba)
    Encoder vs decoderEncoder (BERT) for embeddings/classification; decoder (GPT) for generation; enc-dec (T5) for seq2seq

    Decoding strategies#

    MethodBehaviour
    GreedyArgmax each step; deterministic; can loop
    Beam searchKeep top-B sequences; good for translation, bland for chat
    TemperatureDivide logits by T; T<1 sharper, T>1 more random
    Top-kSample among k most likely tokens
    Top-p (nucleus)Smallest set with cumulative prob ≥ p
    Min-pKeep tokens ≥ min_p × top prob; adapts to confidence
    Repetition / frequency penaltyDown-weight already used tokens
    Constrained / structuredGrammar or JSON-schema masks logits; guarantees valid output
    Speculative decodingDraft model proposes, target verifies in one pass; same output distribution

    Tokenisation details#

    • BPE: start from bytes/chars, repeatedly merge the most frequent pair.
    • WordPiece: merge by likelihood gain (BERT). Unigram: prune a large vocab by likelihood (SentencePiece).
    • Vocab size trade-off: bigger vocab → shorter sequences, larger embedding table (32K–256K typical).
    • Failure modes: digit splitting hurts arithmetic, non-English text costs more tokens, glitch tokens.
    • Special tokens: BOS/EOS, chat-template role markers, tool-call delimiters.

    Reasoning models and test-time compute#

    TechniqueIdea
    Chain-of-thoughtGenerate intermediate steps before the answer; more tokens = more compute per problem
    Self-consistency / best-of-NSample many solutions; majority vote or pick with a verifier
    Process vs outcome reward modelsScore each step vs only the final answer
    RL with verifiable rewards (RLVR)Reward from unit tests or exact-match maths answers; trains long reasoning
    GRPOPPO variant without a value network: advantages relative to a group of samples for the same prompt
    Search at inferenceTree search / MCTS over reasoning steps with a verifier
    Thinking budgetsCap or scale reasoning tokens per request; trade latency and cost for accuracy
    Distilling reasoningFine-tune small models on long reasoning traces from a strong model

    Fine-tuning decision guide#

    Agent anatomy#

    • Tools: functions with JSON-schema args; clear names and descriptions; return concise, structured results.
    • Memory: working (context window), episodic (past runs), semantic (vector store), procedural (instructions/skills).

    • Environment: sandboxed code execution, browser, file system, APIs.
    • Control: step and token budgets, timeouts, human approval for irreversible actions, checkpoints for resume.

    PieceMeaning

    Context engineering#

    • Treat the context window as a budget: system instructions, tools, retrieved docs, history, scratchpad.
    • Put stable content first for prefix caching; volatile content last.
    • Retrieve just in time instead of pre-loading everything; return IDs and let the agent fetch details.
    • Compact long histories: summarise old turns, drop stale tool outputs.
    • Sub-agents with clean contexts for deep subtasks; return condensed results.
    • Structured notes / memory files for long-running tasks.

    1. Role and goal; who the output is for.
    2. Context and constraints; what "good" looks like.
    3. Examples (few-shot), varied and representative.
    4. Output format: schema, XML tags, or JSON mode.
    5. Let the model reason before answering for hard tasks.
    6. Tell it what to do when unsure ("say you don't know").
    7. Version prompts; test them against an eval set like code.

    17Classic ML system design

    The non-LLM design questions in ML engineer loops: a framework plus the key decisions for ten common prompts.

    Framework (45 min)#

    1. Clarify the product goal, users, scale, latency budget, constraints.
    2. Frame as an ML task: input, output, label; is ML even needed?
    3. Metrics: offline (AUC, NDCG) tied to online (CTR, revenue, retention) + guardrails.
    4. Data: sources, labels (explicit, implicit, human), sampling, leakage, privacy.
    5. Features: user, item, context, cross features; freshness; feature store.
    6. Model: baseline → stronger model; justify by data size and latency.
    7. Serving: batch vs online; candidate retrieval → ranking; caching; fallbacks.
    8. Evaluate: offline replay, A/B test, interleaving.
    9. Monitor and iterate: drift, feedback loops, retraining cadence.

    Common traps#

    • Jumping to a deep model before a baseline and a metric.
    • Training–serving skew: features computed differently online.
    • Label leakage from post-event signals (refund flag in fraud features).
    • Ignoring position bias and feedback loops in implicit labels.
    • Random splits on time-dependent data; use time-based splits.
    • No plan for cold start, delayed labels, or class imbalance.
    • Forgetting latency and cost: 100 ms budget shapes model size.

    Video recommendations (home feed)#

    Multi-stage funnel: cheap retrieval over millions of videos, an expensive ranker over hundreds, then policy and diversity re-ranking.

    Framing and metrics

    • Goal: long-term satisfaction, not clicks. Proxy: expected watch time plus survey-based satisfaction.
    • Offline: Recall@k for retrieval; NDCG and AUC for ranking; calibration per head.
    • Online: watch time per user, 7-day retention, diversity. Guardrails: latency, creator fairness, policy violations.

    Data and labels

    • Positives: watched ≥ 30 s or ≥ 50%; negatives: impressed and skipped.
    • Log the position shown; train with it as a feature and fix it at serving to remove position bias.
    • Time-based splits; dedupe bots and autoplay.

    Features and models

    • User: last N watched IDs (sequence encoder), search history, locale, device, time of day.
    • Video: content embedding, age, creator, quality and engagement rates.
    • Cross: user-creator affinity, topic match.
    • Retrieval: two-tower with in-batch negatives and log-Q correction; HNSW or ScaNN index refreshed hourly.
    • Ranking: multi-task DNN (click, watch time, like, dislike) combined by tuned weights.

    Serving and monitoring

    • ~200 ms budget: retrieval 1,000s → ranking 100s → show ~20.
    • Cache user embeddings; precompute for inactive users.
    • Monitor feature drift, index freshness, model calibration; long-term holdout groups.

    Trade-offs

    • Exploration slots for new videos vs short-term watch time.
    • Cold start: content embeddings and a freshness boost.
    • Feedback loops narrow tastes; diversity constraints in re-ranking.

    Payment fraud detection#

    A synchronous decision under 100 ms with heavily imbalanced, delayed labels and an adversary who adapts.

    Framing and metrics

    • Predict P(fraud); map to approve / step-up auth / review / decline with thresholds set from costs: fraud loss vs lost revenue from false declines.
    • Offline: PR-AUC, recall at a fixed false-positive rate, dollar-weighted recall.
    • Online: chargeback rate, approval rate, review queue size.

    Labels

    • Chargebacks arrive 30–90 days later: train on matured windows; use analyst labels for recent data.
    • Fraud is ~0.1%: class weights, careful negative sampling, calibrate afterwards.
    • Declined transactions never get labels: keep a tiny randomised holdout or use counterfactual evaluation.

    Features and model

    • Velocity: transactions per card, device, IP and email over 1 minute, 1 hour, 24 hours.
    • Behaviour: amount vs the user's history, new device, distance from last location, time since account creation.
    • Graph: devices or cards shared with known fraud.
    • Model: gradient-boosted trees plus hard rules; explain with SHAP for analysts.

    Serving and monitoring

    • Online feature store with point-in-time correct training data, so training and serving match.
    • New models run in shadow mode before taking decisions.
    • Fallback to rules if the model times out.
    • Alert on approval-rate shifts and feature drift (PSI); fraudsters adapt within days.

    Trade-offs

    • Decline vs step-up authentication vs manual review.
    • Recall vs customer friction; segment thresholds by merchant risk.

    Enterprise knowledge assistant (RAG)#

    Grounded answers with citations over internal documents, where permissions and prompt injection matter as much as answer quality.

    Requirements and metrics

    • 10K employees, 50K questions/day, first token < 2 s, sources updated within an hour, answers cite sources, never leak documents a user can't open.
    • Retrieval recall@k on a labelled set; faithfulness and correctness (LLM judge calibrated with humans); citation accuracy; deflection rate; thumbs up/down.

    Pipeline

    • Chunk 300–500 tokens along headings; keep title, source, owner, ACL groups, updated_at.
    • Change events trigger incremental re-indexing and deletes.
    • Hybrid retrieval (BM25 + dense, reciprocal rank fusion) top-50 → rerank → best 5–8 chunks.
    • Permission filter applied inside retrieval, never after generation.
    • Prompt: answer only from sources, cite [n], say when the answer isn't there; stream over SSE.

    Safety, cost and evaluation

    • Documents can contain prompt injection: treat retrieved text as data and give the model no write tools.

    • Small model for query rewriting, larger model for answers; semantic cache scoped by permission set.
    • Golden set of 200–500 questions gates every prompt, model or chunking change.

    Trade-offs

    • Long-context stuffing is simpler but costlier and weaker on precision than retrieval.
    • Fine-tuning is for tone and format, not for keeping knowledge current.

    20Rapid-fire interview questions

    Short questions that show up in almost every ML/LLM screen, with the answer to give in one or two sentences.

    Question → crisp answer#

    QuestionAnswer
    Why divide attention scores by √d_k?Dot products grow with dimension; scaling keeps softmax out of saturated regions where gradients vanish.
    L1 vs L2 regularisation?L1 drives weights to exactly zero (feature selection, Laplace prior); L2 shrinks smoothly (Gaussian prior), handles correlated features better.
    Bagging vs boosting?Bagging trains independent models on bootstraps to cut variance (RF); boosting trains sequentially on residuals to cut bias (XGBoost).
    How do you handle class imbalance?Right metric (PR-AUC, recall at precision), class weights or focal loss, resampling inside CV only, threshold tuning, more minority data.
    Why LayerNorm instead of BatchNorm in transformers?Normalises per token, independent of batch size and sequence padding; works at inference with batch size 1.
    What does BatchNorm do at inference?Uses running mean and variance collected in training, not batch statistics.
    Fix vanishing gradients?ReLU-family activations, residual connections, normalisation, good initialisation (He/Xavier), LSTM/GRU gates for RNNs.
    Why AdamW over Adam?Adam's L2 penalty gets scaled by the adaptive learning rate; AdamW decouples weight decay so regularisation behaves as intended.
    What is the KV cache?Stored keys and values of past tokens so each decode step only computes attention for the new token; trades memory for compute.
    Why GQA?Shares K/V heads across query groups; shrinks KV cache and memory bandwidth with little quality loss.
    How does LoRA work?Freezes W and learns a low-rank update BA (rank r); far fewer trainable parameters; can be merged into W after training.
    DPO vs PPO-based RLHF?DPO optimises preferences directly from pairs without a reward model or RL loop: simpler and stabler; PPO can explore beyond the dataset.
    RAG or fine-tuning?RAG for changing or private knowledge with citations; fine-tuning for consistent behaviour, format, tone, or a smaller cheaper model.
    Why is speculative decoding lossless?The target model verifies draft tokens with rejection sampling, so outputs follow the target's distribution exactly.
    Temperature 0 still gives different outputs. Why?Floating-point non-determinism in batched GPU kernels and ties; batch composition changes numerics.
    How do you evaluate a RAG system?Retrieval recall/precision on labelled queries, then faithfulness and answer relevance, plus end-to-end human or judge review on a golden set.
    Data drift vs concept drift?Data drift: input distribution changes (PSI, KS). Concept drift: the input → label relationship changes; detected by falling performance on fresh labels.
    Cross-validation for time series?Forward-chaining (expanding or rolling window) splits; never shuffle future into training.
    Curse of dimensionality?Distances concentrate and data becomes sparse as dimensions grow; KNN and density estimates degrade; reduce dimensions or regularise.
    Explain ROC-AUC to a PMThe chance the model ranks a random positive above a random negative; 0.5 is coin flip, 1.0 is perfect ranking.
    What is calibration and how to fix it?Predicted probabilities match observed frequencies; fix with Platt scaling, isotonic regression or temperature scaling on a held-out set.
    Why does dropout help?Prevents co-adaptation; approximates an ensemble of thinned networks; turned off at inference.
    Prefill vs decode bottlenecks?Prefill is compute-bound (big matrix multiplies over the prompt); decode is memory-bandwidth-bound (reading weights and KV per token).
    How would you reduce LLM serving cost?Cache, route easy queries to small models, shorten prompts, quantise, batch continuously, use prefix caching, distil.
    What is hallucination and how to reduce it?Fluent but unsupported output. Ground with retrieval, ask for citations, allow abstention, lower temperature, verify with checks or a second model.

    Stable softmax and cross-entropy#

    import numpy as np

def softmax(z):                      # z: (n, k)
    z = z - z.max(axis=1, keepdims=True)    # subtract max for stability
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def cross_entropy(logits, y):        # y: integer labels (n,)
    z = logits - logits.max(axis=1, keepdims=True)
    log_probs = z - np.log(np.exp(z).sum(axis=1, keepdims=True))
    return -log_probs[np.arange(len(y)), y].mean()
# gradient w.r.t. logits: (softmax(logits) - one_hot(y)) / n

    Logistic regression with gradient descent#

    def fit_logreg(X, y, lr=0.1, epochs=500, l2=0.0):
    n, d = X.shape
    w, b = np.zeros(d), 0.0
    for _ in range(epochs):
        p = 1 / (1 + np.exp(-(X @ w + b)))  # predicted probabilities
        grad_w = X.T @ (p - y) / n + l2 * w
        grad_b = (p - y).mean()
        w -= lr * grad_w
        b -= lr * grad_b
    return w, b
# predict: (1 / (1 + exp(-(X @ w + b)))) >= 0.5

    k-means#

    def kmeans(X, k, iters=100, seed=0):
    rng = np.random.default_rng(seed)
    C = X[rng.choice(len(X), k, replace=False)]   # (k-means++ is better)
    for _ in range(iters):
        d = ((X[:, None, :] - C[None, :, :]) ** 2).sum(-1)   # (n, k)
        labels = d.argmin(1)
        newC = np.array([X[labels == j].mean(0) if (labels == j).any() else C[j]
                         for j in range(k)])
        if np.allclose(newC, C): break
        C = newC
    return C, labels

    Scaled dot-product attention with a causal mask#

    def attention(Q, K, V, causal=True):  # (T, d) each, single head
    d = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d)                 # (T, T)
    if causal:
        T = scores.shape[0]
        scores = np.where(np.tril(np.ones((T, T))) == 1, scores, -1e9)
    w = softmax(scores)                           # rows sum to 1
    return w @ V                                  # (T, d)
# multi-head: split d into h heads, run per head, concatenate, project

    ROC-AUC from scratch#

    def roc_auc(y, scores):
    # probability a random positive outranks a random negative (ties count ½)
    order = np.argsort(scores)
    ranks = np.empty(len(scores)); ranks[order] = np.arange(1, len(scores) + 1)
    for s in np.unique(scores):                    # average ranks for ties
        m = scores == s; ranks[m] = ranks[m].mean()
    pos = y == 1; n_pos, n_neg = pos.sum(), (~pos).sum()
    return (ranks[pos].sum() - n_pos * (n_pos + 1) / 2) / (n_pos * n_neg)

    Top-p (nucleus) sampling#

    def sample_top_p(logits, p=0.9, temperature=1.0, rng=np.random.default_rng()):
    probs = softmax((logits / temperature)[None, :])[0]
    order = np.argsort(-probs)
    cum = np.cumsum(probs[order])
    keep = order[: np.searchsorted(cum, p) + 1]   # smallest set with mass ≥ p
    kept = probs[keep] / probs[keep].sum()
