    How to use this sheet#

    1. New to Python: foundations, then market data. Every later script is "fetch a DataFrame, compute, decide".
    2. Building a strategy: indicators → signals → playbook → testing, in that order.
    3. Before any real order: execution, the backtest-trust ladder, position sizing and the go-live checklist at the end.
    4. Keep OpenAlgo in analyze mode (simulated orders) the whole time you learn.
    Educational, not investment advice. Condensed in our own words from OpenAlgo Open Varsity: Algo Trading with Python. Code here is short illustrative idiom in the course's style, not a copy; SDK field names can change between versions, so print a response once before relying on its shape.

    01Foundations: setup, secrets, the client and Python essentials

    OpenAlgo Open Varsity · Algo Trading with Python · chapters 1–2 (getting started, Python essentials)

    Set up once#

    1. Install Python (on Windows tick "Add Python to PATH"); check with python --version.
    2. Install VS Code and its Python extension.
    3. Run OpenAlgo locally; the dashboard opens at http://127.0.0.1:5000. Copy your API key from its API Key page.
    4. pip install uv, then uv init my-trading, cd my-trading, uv add openalgo.
    5. Run scripts with uv run python file.py: one isolated, reproducible project per idea.

    Keep secrets out of code#

    • Put OPENALGO_API_KEY, OPENALGO_HOST (and later OPENALGO_WS_URL) in a .env file; load it with python-dotenv and read with os.getenv().
    • Add .env to .gitignore; commit a blank .env.example instead.
    • Treat the key like an ATM PIN: never hard-code it, paste it in chat or push it to GitHub. Replace any placeholder default before running.

    The client, analyze mode and the safe-response pattern#

    import os
from dotenv import load_dotenv
from openalgo import api, ta

load_dotenv()
client = api(api_key=os.getenv("OPENALGO_API_KEY"),
             host=os.getenv("OPENALGO_HOST", "http://127.0.0.1:5000"))

# confirm analyze mode is ON while learning
print(client.analyzerstatus()["data"])
resp = client.quotes(symbol="SBIN", exchange="NSE")
# every reply: status + data (or message)
if resp.get("status") == "success":
    q = resp["data"]
    pct = (q["ltp"] - q["prev_close"]) / q["prev_close"] * 100
else:
    print("failed:", resp.get("message"))
    • Analyze mode simulates orders; nothing reaches the exchange. client.analyzertoggle(mode=True) switches it on. Going live should be a deliberate act, never an accident. (The course shows the mode under both mode and analyze_mode keys, so print it once.)
    • Payloads sit one layer down: resp["data"] for most calls, resp["results"] for batch calls. Forgetting that layer is the commonest beginner error.
    • client.funds() → availablecash, utiliseddebits, m2mrealized, m2munrealized. client.intervals() lists supported timeframes.
    • Wrap every live call in try/except so one bad reply can't kill the bot; an unknown symbol returns an HTTP 400 "not found" (check master contracts are downloaded).

    Discovering instruments and lot sizes#

    info = client.symbol(symbol="SBIN", exchange="NSE")["data"]

    • Sample lot sizes: NIFTY 65, BANKNIFTY 30, RELIANCE future 500, GOLDM / CRUDEOIL / SILVERM 1. Ticks: SBIN 0.05, RELIANCE 0.1, BANKNIFTY future 0.2, CRUDEOIL 1.0.
    • Exchanges revise lots, so look them up every time; never hard-code. One NIFTY future lot ≈ 65 × 23,810 ≈ ₹15.5 lakh.
    • Weekly index options mean one strike has many expiries; the nearest is usually the most active.

    Quotes, multiquotes and depth#

    CallReturnsUse
    quotes(symbol, exchange)["data"]ltp, open, high, low, prev_close, bid, ask, volume, oiOne snapshot
    multiquotes(symbols=[{...}, ...])["results"]Per item: symbol, exchange, dataMany symbols, mixed exchanges, one request (use beyond 2–3 symbols)

    change % = (ltp − prev_close) / prev_close × 100spread = best ask − best bid (GOLDM: 22 points ≈ 0.015%)buy pressure % = buy qty / (buy + sell) × 100range position % = (ltp − low) / (high − low) × 100
    • NSE and BSE cash trade 09:15–15:30 IST; depth is empty and quotes can show zeros when the market is shut, so guard bids[0] and zero division. Practise depth on MCX in the evening.
    • Check the spread before trading anything unfamiliar. Imbalance and OI are supporting clues, never triggers on their own.

    Historical candles#

    from datetime import datetime, timedelta
end = datetime.now(); start = end - timedelta(days=120)
df = client.history(symbol="TCS", exchange="NSE", interval="D",
                    start_date=start.strftime("%Y-%m-%d"),
                    end_date=end.strftime("%Y-%m-%d"))
# DataFrame indexed by timestamp: open high low close volume oi
    • Intervals: 1m 3m 5m 10m 15m 30m 60m 1h D. Ten calendar days of TCS: D 7 rows, 1h 49, 15m 175, 5m 525.
    • Calendar days are not sessions: 7 days gave 6 rows, 30 gave 21, 90 gave 59. Ask for a generous window and count rows.
    • Intraday timestamps carry +05:30 IST; the first 5-minute bar is 09:15, the last 15:25. oi is 0 for stocks.
    • source="db" reads OpenAlgo's local store instead of the broker; wrap it in try/except. Build dates from datetime so scripts never go stale.

    Resample the right way#

    OHLCV = {"open": "first", "high": "max", "low": "min",
         "close": "last", "volume": "sum"}
weekly = df.resample("W").agg(OHLCV).dropna()  # "ME" = month-end
hourly = df5.resample("60min").agg(OHLCV).dropna()

df = pd.read_csv("tcs.csv", index_col=0, parse_dates=True)
    • Never average OHLC bars. First, max, min, last, sum is the only recipe.
    • Resampling only goes up (5m → 1h, never back). Download the smallest interval you will need.

    NumPy in five moves#

    • Arrays: np.array, np.arange(1, 6) (6 excluded), np.linspace(100, 200, 5); check shape, ndim, size, dtype (prices are float64).
    • Indexing: a[-1] latest; a[1:4] is three items; a[-5:] last five; 2D p[:, -1] last column.
    • Vectorise: closes * 1.05, closes * qty: no Python loops over prices.
    • Aggregate: mean, max, min, std, median, sum, cumsum; axis=1 across rows, axis=0 down columns.
    • Masks: mask = closes > closes.mean(); closes[mask]; mask.sum(); np.where(cond, 1, 0): the seed of every signal.

    Five RELIANCE closes 1305.0 … 1312.7: mean 1309.04, std 6.84, three days above average.

    Matplotlib: precise charts saved to PNG#

    • fig, ax = plt.subplots(figsize=(9, 4.5)); draw with plot, bar, hist, scatter, fill_between, axhline; finish with plt.savefig(path, dpi=110, bbox_inches="tight") (headless: no window appears).
    • No weekend gaps: plot against range(len(df)) and label every Nth tick with df.index.strftime("%d %b").
    • Price over volume: plt.subplots(2, 1, sharex=True, gridspec_kw={"height_ratios": [2, 1]}).
    • Overlays (SMA/EMA from openalgo.ta), buy/sell markers (^, v), hand-built candles (wick line + body bar), equity curve with a line at 1.0, drawdown filled to zero, and rebasing to 100 for comparing stocks.
    • Seaborn for statistics: return histograms, correlation heatmaps (from returns, not prices), seasonality grids.
    • Markers sit on the signal bar's close; a backtest must act on the next bar.

    Plotly: interactive candles#

    import plotly.graph_objects as go

    • Set row= and col= on every trace. write_image needs kaleido and loses interactivity.

    Streamlit: a dashboard in one script#

    import streamlit as st

# seconds for quotes, hours for daily history
@st.cache_data(ttl=60)
def load(sym, exch):
    return client.history(symbol=sym, exchange=exch, interval="D",
                          start_date=start, end_date=end)

sym = st.text_input("Symbol", value="RELIANCE")
exch = st.selectbox("Exchange", ["NSE", "NFO", "MCX"])
df = load(sym, exch)
st.metric("Last close", f"{df['close'].iloc[-1]:,.2f}")
st.line_chart(df["close"])
    • Launch with streamlit run app.py (not python); it opens at localhost:8501.
    • The whole script re-runs from the top whenever a widget changes. Write it as if it runs once, and cache every network call, or each slider move refetches history. Plain variables don't persist between runs.
    • Building blocks: st.title, st.metric, st.table, st.line_chart, st.plotly_chart(fig, use_container_width=True); widgets text_input, selectbox, slider. A watchlist board is one multiquotes call; a scanner is a loop of history + ta.rsi.

    05Signals and scanning

    OpenAlgo Open Varsity · Algo Trading with Python · chapters 17–18 (from indicators to signals, scanning and screeners)

    The signal pipeline#

    1. Fetch history.
    2. Compute indicators.
    3. Write raw conditions: (close > ema50) & (rsi > 50).
    4. Find turning points with crossover / crossunder.
    5. De-duplicate with exrem so buys and sells alternate.
    6. Shift one bar: .shift(1).
    7. Hand entries and exits (boolean Series) to the backtester.

    A signal is one True/False answer per bar, aligned to timestamps, not a single decision.

    EMA crossover, done properly#

    c = df["close"]
fast, slow = ta.ema(c, 20), ta.ema(c, 50)
S = lambda a: pd.Series(a, index=c.index)
buy  = S(ta.crossover(fast, slow))
sell = S(ta.crossunder(fast, slow))
buy, sell = S(ta.exrem(buy, sell)), S(ta.exrem(sell, buy))
entries = buy.shift(1).fillna(False)    # act on the NEXT bar
exits   = sell.shift(1).fillna(False)
inpos   = S(ta.flip(buy, sell))          # 1 while holding
entry_px = S(ta.valuewhen(buy, c, 1))   # price at the last buy

    RSI example: raw buys 7 → 2 and raw sells 47 → 3 after exrem. Without it you stack repeated buys before any sell.

    Look-ahead: the silent backtest killer#

    • A signal computed from today's close only exists after the close. Trading on that same close assumes you knew the future.
    • Fix: signal.shift(1) for crossovers, RSI levels and breakouts alike; compare breakouts with the previous bar's level.
    • Remove the shift and an untradeable backtest becomes a flattering one. The same applies to charts: markers sit on the signal bar's close.

    Scanner = universe + loop + rule#

    rows = []
for s in universe:
    try:
        df = client.history(symbol=s, exchange="NSE", interval="D",
                            start_date=start, end_date=end)
    except Exception:
        continue
    if not isinstance(df, pd.DataFrame) or df.empty:
        continue  # one bad symbol must not kill the scan
    c, h, v = df["close"], df["high"], df["volume"]
    rows.append({"symbol": s,
        "rsi": float(ta.rsi(c, 14).iloc[-1]),
        "above_ema50": c.iloc[-1] > ta.ema(c, 50).iloc[-1],
        "breakout": c.iloc[-1] > np.asarray(ta.highest(h, 20))[-2],
        "rvol": v.iloc[-1] / v.rolling(20).mean().iloc[-1],
        "ret20": c.iloc[-1] / c.iloc[-21] - 1})
board = pd.DataFrame(rows).sort_values("ret20", ascending=False).reset_index(drop=True)
board.index += 1                                   # 1-based ranks

    Filters: RSI < 30 or > 70, close above EMA50, 20-day breakout against yesterday's high, RVOL > 1.5. For a live snapshot of many names, one multiquotes() call beats a loop; loop history() only when you need time-series indicators. The same loop works for NFO and MCX (whose futures symbols carry the expiry).

    Backtest by hand first#

    fast, slow = c.ewm(span=10).mean(), c.ewm(span=30).mean()
signal = (fast > slow).astype(int)
pos    = signal.shift(1).fillna(0)          # yesterday's decision
ret    = c.pct_change().fillna(0)
equity = 100000 * (1 + pos * ret).cumprod()
bh     = 100000 * (1 + ret).cumprod()       # always compare

    SBIN 10/30 EMA, no costs: +12.71% vs buy-and-hold +28.75%. Positive is not the same as good.

    VectorBT with costs#

    import vectorbt as vbt
entries = (fast > slow) & (fast.shift(1) <= slow.shift(1))
exits   = (fast < slow) & (fast.shift(1) >= slow.shift(1))
pf = vbt.Portfolio.from_signals(
    c, entries, exits, init_cash=100000,
    fees=0.001, slippage=0.0005, freq="1D",
    direction="longonly")
pf.total_return(); pf.trades.count()
pf.max_drawdown(); pf.stats()
    • SBIN with costs: +10.87%, 6 trades, ≈ ₹1,136 fees, max drawdown ≈ 19.7%, 20% wins, Sharpe ≈ 0.75. Going both ways (direction="both"): −6.25%.
    • Same settings on GOLDM 20/50: −11.43% vs −3.05% buy-and-hold, −32% drawdown. Results don't transfer between instruments.

    Optimisation: plateaus beat peaks#

    • Grid = small lists → itertools.product → drop invalid pairs (fast ≥ slow) → one backtest per combo → rank. Every extra value multiplies work and false winners.
    • Vectorise: 2D entries/exits with a MultiIndex of (fast, slow), one from_signals call, pf.sharpe_ratio().idxmax(), then .unstack("slow") for a heatmap.
    • Broad green plateau = robust; a lone green cell beating its neighbours by a mile, or a winner with very few trades, is luck.
    • RELIANCE 16-combo grid: best 5/40 at +3.10% with 0.1% fees. Adding realistic costs dropped 5/30 from 4.23% to 1.76% and changed the winner; on GOLDM most combos lost. Re-optimise per instrument, with costs, then validate out of sample.

    Walk-forward: the only number that counts#

    1. Split by time, never shuffle: first ≈ 70% in-sample, last ≈ 30% out-of-sample.
    2. Tune on in-sample only; pick the best Sharpe.
    3. Run that one winner on the unseen slice.
    4. Roll it: tune 250 bars, test the next 100, slide by 100, repeat; log picks and results.
    5. Check parameter stability, the in/out gap and trade counts.

    RELIANCE, 610 bars (427 / 183): EMA 30/60 won in-sample at +15.90% (Sharpe 0.71) and lost −4.57% out of sample; rolling windows: −3.30%, −6.07%, −4.15%. Expect honest results from simple ideas to look like this, and deflate any winner picked from many tries.

    Machine learning: workflow over model#

    • Features: RSI, ATR, distance from EMA, recent returns; dropna() the warm-up rows.
    • Label: next bar up, (c.shift(-1) > c).astype(int). The bar to beat is the base rate: always guessing the majority class.
    • Split by time (train_test_split(..., shuffle=False)) and fit any scaler on the training set only; then walk-forward (train 300, test 100, slide).
    • Models: logistic regression, random forest (depth 4, 100–150 trees), a small neural net MLPClassifier((16, 8)) with scaled inputs. Bigger nets fit noise faster.

    Logistic regression47.0%
    Random forest47.7%
    Neural net49.0%

    None beat the baseline, and walk-forward averaged ≈ 49.5%. Expect coin-flip accuracy; feature importance is a hint, not proof.

    Anatomy of the capstone bot#

    1. Fetch daily history.
    2. Engineer features and the label.
    3. Train, then predict the latest row.
    4. Act: BUY 1 (MARKET, CNC) on an up signal; placesmartorder(position_size=0) to flatten on a down signal.
    5. Alert via Telegram inside try/except so a missing link can't crash it.
    6. Schedule after the close with cron, Task Scheduler or OpenAlgo's strategy host.

    Gaps to fill before real money: a proper loop, risk checks, sizing (below) and real logging. Run in analyze mode, small, with a human watching.

    Position sizing by rupee risk#

    risk budget = capital × 1%qty = floor(risk budget ÷ (entry − stop)) round DOWN, guard zero distanceATR stop = entry − 2 × ATR(14) → qty = budget ÷ (2 × ATR)F&O: units = (qty // lot_size) × lot_size whole lots onlyheat = Σ qty × (entry − stop) over open trades ≤ 6% of capital
    • RELIANCE entry 1,400, stop 1,372 → ₹28 risk a share: on ₹5 lakh at 1% (₹5,000) that is 178 shares (our illustration).
    • NIFTY entry 25,900, stop 25,750 → ₹150 a unit; with ₹5,000 at risk that is 33 units, which rounds down to zero lots of 65: the trade is too big for the account.
    • Heat example: RELIANCE 40 × 28 + INFY 30 × 30 + TATASTEEL 200 × 4 = ₹2,820. Correlated positions are one bigger bet; size them together.
    • Survival maths: with a 55% win rate, risking 2% a trade survives losing streaks that 20% cannot; a 50% loss needs +100%. Don't raise size after a winning run, and don't let a tight stop create an oversized position.
    • Pull capital from funds()["data"]["availablecash"] and price from quotes(); wrap it all in one position_size() helper.

    10Checklists and quick reference

    Read this before the first real-money order.

    Go-live checklist#

    1. Keys live in .env, never in code or Git.
    2. Every call checks status and survives errors.
    3. Signals are shifted one bar; breakouts use the prior bar's level.
    4. The backtest has realistic fees and slippage and beats the benchmark.
    5. It holds out of sample with stable parameters and enough trades.
    6. Size comes from rupee risk, rounded down to whole lots; total heat is capped.
    7. Intraday code stops entries before the MIS cutoff and forces flat.
    8. Multi-leg orders check every leg's status.
    9. Weeks of analyze-mode running, logs and alerts, then small live size with a human watching.
